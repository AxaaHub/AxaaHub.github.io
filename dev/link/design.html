一、界面效果

工具目标：输入一个链接，查看经过的地址、每步跳转方式，以及检查会话实际到达的位置。正式工具的计划入口为 axaahub.github.io/dev/link/。

本文件是设计文档。下面是静态界面效果稿，网址使用前面检查过的京东短链案例；状态、耗时与交互控件用于评审，不会再次请求这些网址，也不代表检测服务已实现。预览图直接内嵌在 HTML 中，单独打开本文件即可查看。

桌面 · 浅色

沿用现有 JSON 工具的蓝灰配色、白色面板与按钮风格。输入区集中在顶部，最近查询紧接输入区；结果先呈现实际终点，再展开完整链路。

桌面 · 深色

展开深色界面效果稿

控件位置与浅色一致，保留最近查询区；重点地址使用蓝色区域，登录状态使用琥珀色提示。

手机布局

展开手机界面效果稿

窄屏下使用单列布局。最近查询提供重查和删除操作；链路改为纵向步骤卡片，长网址分行显示，复制内容仍保留完整链接。

二、页面信息结构

区域展示内容交互约定
页面顶部工具名称、简短用途、主题切换主题支持跟随系统、浅色、深色；工具页风格参考现有 JSON 工具。
链接输入待检查网址、填入示例、检测方式、设备类型仅接受 HTTP / HTTPS；自动去除首尾空白。选择桌面或手机访问配置。
最近查询近期网址、查询时间、检测方式、设备与状态摘要在当前浏览器保存最近 20 条；支持回填重查、删除单条、清空与关闭记录。
检查按钮开始检查、检查中状态、停止操作提交时固定本次输入与配置，避免后续编辑造成结果与输入混淆。
结果摘要实际最终地址、终止原因、地址数量、跳转次数、总耗时清楚区分正常结束、登录页面、验证码、超时和请求失败。
回跳目标从已知 URL 参数中提取的目标，例如 ReturnUrl标明提取来源与“尚未访问”，与浏览器实际终点分别展示。
跳转链路步骤、状态码、完整网址、跳转类型、单步耗时长查询参数默认折叠；支持展开查看与逐条复制。
结果操作复制最终地址、复制全部链路、导出 JSON / 文本复制与导出始终使用完整原始网址，保留查询参数及编码。

首版包含单个链接检查、结果阅读和浏览器最近查询，使用时不要求安装浏览器扩展。历史记录保存在本地，无需新增数据库；批量检查与团队管理暂不纳入首版。

最近查询（浏览器本地记录）

正式工具使用 localStorage 保存最近查询。正常浏览模式下，刷新或关闭后重新打开同一站点仍可读取；记录属于当前浏览器配置与站点，不会自动跨设备同步。

项目设计约定
保存范围完整原始网址、查询时间、检测方式、设备类型、最终地址与结束状态摘要。完整跳转链路通过导出功能保存，首版历史列表仅保存摘要。
条数与排序最多 20 条，最新在前。相同完整网址、检测方式和设备组合只保留最近一次；查询参数不剥离或重排。
写入时机已发起的检查正常结束、失败或停止后写入；输入校验未通过时不写入。记录使用本次检查开始时固定的输入与配置。
回填与重查点击记录回填网址与当时配置，不自动联网；点击“重查”发起新检查。历史摘要显示上次查询时间，不当作最新结果。
删除与清空支持删除单条和清空全部。清空全部需要确认，只清理本工具历史，保留主题偏好与同站点其他工具的数据。
记录开关默认开启，可随时关闭。关闭后停止新增，已有记录仍可查看或删除。
容量与降级仅保存小量摘要，并设置应用内总大小上限；超限优先淘汰旧项，原始网址不截断。浏览器拒绝存储、容量不足或记录损坏时说明原因，不阻断链接检查。

存储使用独立键 axaahub.link.recent.v1，并带数据版本号；清空操作针对该键，不调用会清除全站数据的 localStorage.clear()。历史列表不额外上传或同步，提交检查的网址仍需要发送给检测后端。

清理站点数据会移除历史；无痕会话中的记录通常在关闭会话后删除。正式验收以 HTTPS 站点为准，直接用 file:// 打开时的存储行为不作保证。参见 MDN localStorage 与 Web Storage API。

三、检测模式与边界

快速检查

由后端逐跳发送 GET 请求，读取 301、302、303、307、308 响应中的 Location，解析相对地址，并记录状态和耗时。保留本次检查会话内必要的 Cookie，用于同一跳转流程。

适合纯 HTTP 重定向。遇到返回 200 的 HTML 页面时，展示“HTTP 链路已结束”；即使正文中发现疑似脚本目标，也只能把它作为未验证线索，不能直接当作已经到达的地址。

浏览器检查

计划作为默认模式：在后端启动独立浏览器会话，让页面实际运行，记录主页面导航及其 HTTP 重定向链，覆盖常见 JavaScript、Meta Refresh 和延迟跳转。

  • 统计真正发生的页面导航；图片、脚本、广告和接口请求不计为跳转步骤。
  • 有明确证据时标注 HTTP 重定向、脚本跳转或刷新跳转；无法精确识别来源时标为“页面导航”。
  • 检测到登录或验证码等停止条件时结束，保留已取得的链路；弹窗、下载及非 HTTP 协议单独记录终止原因。
  • 使用全新、未登录的会话；桌面与手机配置可能得到不同结果，页面始终显示本次使用的配置。
实际终点与推断目标要分开。在示例中，浏览器实际到达京东登录页；商品地址来自登录页的 ReturnUrl。结果应保留这两项信息，并把商品地址标为未访问，而不能把它写成最终已经打开的页面。

浏览器检查仍受网络、地区、登录状态、站点反自动化策略和观察时长影响。超时或受限时提供部分结果与终止原因，不使用“完整”标签掩盖尚未观察到的后续跳转。

四、交互流程与状态

1
输入链接：粘贴网址，或从最近查询回填，选择检测方式和设备类型。回填时不自动请求；点击检查或重查后才联网。输入无效时在输入区说明原因。
2
检查中：按钮进入运行状态，显示已发现的步骤；提供停止操作，避免重复提交同一任务。
3
查看结果：优先看到实际终点与结束原因，再查看每步网址、状态、参数及耗时。
4
复制或导出：可以复制单个完整网址，也可以导出本次检查的全部记录。开启记录时，本次已发起检查的配置与结果摘要保存到浏览器最近查询。
状态界面表现保留的结果
尚未检查输入区域与简短使用提示，结果区显示占位内容。无历史结果时不填充虚构数据。
检查中显示当前步骤数、已耗时和停止按钮。已观察到的步骤逐项追加。
正常结束显示最终地址、成功状态与统计。观察窗口内的完整导航记录。
登录 / 验证码明确标注停止位置；存在回跳参数时另列目标。截至当前的链路与目标提取依据。
超时 / 跳转过多显示“部分结果”及具体限制。已经完成的步骤可复制与导出。
DNS / TLS / 网络失败指出失败步骤与可理解的错误。失败前的链路，不编造 HTTP 状态码。
用户停止显示“已停止”，允许重新检查。停止前已经取得的记录。

五、部署方案

前端作为静态页面部署在 GitHub Pages，后端负责网络请求和浏览器运行。正式入口为 /dev/link/，首页使用 index.html；本设计文档使用 design.html，正式入口已创建，本轮仅在本地运行。

用户浏览器
  ↓ 提交网址与检测选项
GitHub Pages：/dev/link/
  ↓ HTTPS 调用检测 API
独立后端：/api/trace
  ↓ HTTP 请求 / 独立浏览器会话
目标网站
  ↓
返回跳转步骤、实际终点与结束原因

GitHub Pages 托管静态 HTML、CSS 和 JavaScript；任意跨域链接的状态、跳转头和页面脚本执行需要后端处理。浏览器的 redirect: "manual" 会产生不可直接读取状态与响应头的 opaqueredirect，不能据此实现通用的前端跳转检测。

后端部署选择

方案实现方式适用条件与取舍
现有 VPSNode.js HTTP 服务 + Playwright / Chromium，使用容器或进程服务运行。有现成服务器时优先考虑；可以控制网络出口和运行环境，需要维护进程及浏览器。
CloudflareWorkers 提供 API，Browser Run 提供浏览器会话。减少自建浏览器运行环境的维护；需核对账户的浏览器额度、并发限制及计费规则。

当前待定：后端部署位置与接口访问范围。界面设计不依赖最终选择；确定部署位置后，再落实环境配置、访问控制和发布流程。

方案依据：GitHub Pages 官方说明、Fetch 响应类型说明、Playwright 请求与重定向事件、Cloudflare Browser Run。

六、接口与运行约束

接口示例

请求采用 POST /api/trace。下面的 JSON 用于说明字段，属于设计样例；任务执行、进度传递与取消机制将在后端方案确定后实现。

{
  "url": "https://vip.qust.me/go/o/0f111b2695fa",
  "mode": "browser",
  "profile": "desktop"
}

结果至少包含原始输入、本次配置、逐步记录、最终实际地址、可识别的回跳目标，以及本次结束原因：

{
  "mode": "browser",
  "profile": "desktop",
  "hops": [
    {
      "index": 1,
      "url": "https://vip.qust.me/go/o/0f111b2695fa",
      "status": 302,
      "transition": "http_redirect",
      "nextUrl": "https://u.jd.com/F1PFDWZ",
      "elapsedMs": 120
    }
  ],
  "final": {
    "url": "https://passport.jd.com/new/login.aspx?ReturnUrl=...",
    "status": 200,
    "title": "京东-欢迎登录"
  },
  "declaredTargets": [
    {
      "source": "query.ReturnUrl",
      "url": "https://item.jd.com/10221721416742.html",
      "visited": false
    }
  ],
  "termination": { "reason": "login_page" },
  "durationMs": 2310,
  "isPartial": true
}
上方响应省略了中间步骤和较长的查询参数。正式返回、复制与导出均保留实际观测到的完整网址；派生的简化地址不能覆盖原始记录。未收到 HTTP 响应时，状态码使用空值并另列错误信息。

访问与资源限制

  • 目标范围：仅允许公开的 HTTP / HTTPS 地址。每次连接与重定向都校验目标，浏览器导航及子资源也要受网络出口限制，阻止本机、内网与云元数据地址。
  • 会话隔离：每次检查使用独立会话，不携带用户本机的登录 Cookie；结束、取消或超时后释放浏览器资源。
  • 运行上限：初步建议最多 20 次跳转、总观察时间 30 秒，并设置并发与调用频率限制；数值将在部署环境确定后调整。
  • 前端输出：网址、标题和错误信息按文本渲染，避免把目标页面提供的内容当作可执行 HTML。
  • 接口权限：CORS 仅控制浏览器来源，仍需独立的访问控制或限流。是否仅供本人使用，列为部署前的待确认项。
  • 密钥与记录：密钥放在后端环境中。最近查询保存在浏览器，无需后端历史数据库；检测请求仍由后端处理。服务端日志避免保存带令牌等敏感参数的完整网址。

七、验收与待确认事项

验收场景

下面是后续实现时的验收计划，不表示这些功能已经实现或测试通过。

场景预期
多级 HTTP 跳转、相对 Location逐跳保留地址、状态和先后顺序，相对地址解析正确。
JavaScript、刷新与延迟导航浏览器模式能记录真实发生的导航；观察超时仍保留部分结果。
进入登录页并附带回跳参数登录页作为实际终点，参数中的目标单独列出并标为未访问。
循环、过多跳转、超时或网络失败按上限停止，说明原因，已取得的链路仍可导出。
内网、回环及重定向后的受限地址在连接前拒绝，不仅检查最初输入的地址。
最近查询与持久化刷新与重新打开后可读取最近记录；重查回填正确；相同网址、模式、设备组合更新最近一次，超过 20 条淘汰最旧记录。
删除、关闭与存储不可用删除单条或清空只影响本工具历史；关闭记录后不再新增；浏览器拒绝存储或容量不足时仍能检查链接。
长网址、移动端与深色主题文字可读、没有页面横向溢出；复制结果完整，参数展开后可检查。

实现后的自动化验证优先使用隔离的可控测试页面，不调用真实登录、付款或会触发业务操作的流程；实际短链只用于补充验证，并记录检查配置与时间。

待确认事项

  1. 界面方向：输入在上、最近查询紧随其后、摘要与链路在下；桌面列表与手机步骤卡片是否符合预期。
  2. 默认方式：建议默认浏览器检查，保留快速检查作为可选方式。
  3. 后端位置：已有 VPS 或 Cloudflare Workers + Browser Run。
  4. 访问范围：仅本人使用，或公开提供给其他访问者。
